\section{Sequence Planning} \label{sec:sequence_planning}

In this section, we introduce the remaining modules $\initpose$ and $\simul$ that are used to generate candidate poses and simulate the stability of the scene, respectively.
Then, we present the Monte Carlo Tree Search (MCTS) algorithm that uses these modules to explore the space of possible stacking sequences and find an optimal sequence of object placements.

\subsection{Initial Pose Sampling}
The initial pose sampler generates a candidate object, orientation, and planar
translation from the current state $\state_k=(\scene_k,\inventory_k,\target)$.
Let $\mathcal{G}_{i,R}(\state_k)$ denote the feasible planar sampling grid for
object $i$ and orientation $R$, and let
$\hat{q}_{k+1}=(R,(\planar,z_{i,R}(\planar;\state_k)))$.
The sampler is defined by
\begin{equation*}
    \begin{aligned}
        \initpose(i,R,\planar\mid\state_k)
        &= \pi_{xy}(\planar\mid i,R,\state_k)
           \pi_\text{unif}(i,R\mid\state_k),\\
        \pi_{xy}(\planar\mid i,R,\state_k)
        &\propto
        \exp\!\left(\score(\planar\mid i,R,\state_k)/\tau\right).
    \end{aligned}
\end{equation*}
where $\pi_\text{unif}(i,R\mid\state_k)$ is uniform over
$i\in\inventory_k$ and the finite rotation set $\mathcal{R}$.
The distribution $\pi_{xy}$ is defined over
$\planar\in\mathcal{G}_{i,R}(\state_k)$, and $\tau>0$ controls the preference
for higher-scoring planar locations. The initial height $z_{i,R}$ is computed
from the scene geometry, while the full pose is subsequently refined by the
pose optimization module $\poseopt$.
For brevity, the dependence of the score on $\state_k$ is omitted below.
The proposal score $\score(\planar\mid i_{k+1},R)$ is formulated as a weighted sum of several geometric features that are computed based on the scene $\scene_k$, the target shape $\target$, and the object $i_{k+1}$:
\begin{equation*}
  \begin{split}
    \score(\planar\mid i_{k+1},R) ={}& w_\text{s}\score_\text{s}(\planar\mid i_{k+1},R)+w_\text{f}\score_\text{f}(\planar\mid i_{k+1},R) \\
    &+w_\text{b}\score_\text{b}(\planar\mid i_{k+1},R)-w_\text{h}\score_\text{h}(\planar\mid i_{k+1},R),
  \end{split}
%   \label{eq:initial_pose_score}
\end{equation*}
where $\score_\text{s}$ is the support area score map, $\score_\text{f}$ is the filled floor area score map, $\score_\text{b}$ is the boundary proximity score map, and $\score_\text{h}$ is the height score map, respectively with weight parameters $w_\text{h}$, $w_\text{s}$, $w_\text{f}, w_\text{b} > 0$.

Intuitively, the score $\score_\text{s}$ encourages the object to be placed on a larger support area, the score $\score_\text{f}$ encourages the object to fill the empty floor area, the score $\score_\text{b}$ encourages to fill the boundary of the target shape $\target$ first, and the last score $\score_\text{h}$ encourages the object to be placed at a lower height to improve stability.
The visualization examples of the score maps are shown in Fig. \ref{fig:score_map} and the details of the score map computation will be described in the appendix.

\begin{algorithm}[t]
  \caption{Initial pose sampling}
  \label{alg:initial_pose_sampling}
  \begin{algorithmic}[1]
    \Require State $\state_k=(\scene_k,\inventory_k,\target)$, rotation set $\mathcal{R}$
    \State Sample $i_{k+1}\sim\operatorname{Unif}(\inventory_k)$ and
           $R\sim\operatorname{Unif}(\mathcal{R})$
    \State Construct the feasible planar grid
           $\mathcal{G}_{i_{k+1},R}(\state_k)$
    \State Evaluate $\score(\planar\mid i_{k+1},R,\state_k)$ for all
           $\planar\in\mathcal{G}_{i_{k+1},R}(\state_k)$
    \State Sample $\planar$ from $\pi_{xy}(\planar\mid i_{k+1},R)$
    \State Set $\hat{q}_{k+1}=(R,(\planar,z_{i_{k+1},R}(\planar;\state_k)))$
    \State \Return $(i_{k+1},\hat{q}_{k+1})$
  \end{algorithmic}
\end{algorithm}

\subsection{Simulation Module}

As mentioned in Sec. \ref{sec:overview}, after $\poseopt$ refines the candidate pose $\hat{q}_{k+1}$ to find a locally optimal placement pose $q_{k+1}$, the simulation module $\simul$ acts as a transition function $\state_{k+1} = \transition(\state_{k}, \action_{k})$ which simulates the physical behavior of the scene $\scene_{k+1}$ after placing the object $\object_{i_{k+1}}$ at the placement pose $q_{k+1}$.
The simulation module $\simul$ works in two steps: first, freezing the objects in the scene $\scene_k$ and simulate the newly placed object $\object_{i_{k+1}}$ to further refine the pose, and second, simulate the entire scene $\scene_{k+1}$ to ensure that the entire scene is stable.

For both steps, we use the early-termination condition to terminate the simulation if the scene is stable or expected to be unstable, and the simulation statistics are used to evaluate the reward of the action $\action_k$.
The early-termination condition is based on the mass-normalized kinetic energy $E_{\text{kin},i}$ and the accumulated energy $E_{\text{acc},i}$ of the object $\object_i$ in the scene $\scene_{k+1}$, which are defined as
\begin{align*}
    E_{\text{kin},i}(t) = \frac{1}{2m_i}\mathcal{V}_i^\top M_i \mathcal{V}_i, \quad 
    E_{\text{acc},i}(t) = \sum_{s=0}^{t} \sqrt{E_{\text{kin}(s),i}} \Delta t
\end{align*}
where $\mathcal{V}_i \in \real^6$ is the linear and angular velocity of the object $\object_i$, $M_i \in \real^{6\times 6}$ is the mass matrix of the object $\object_i$, $m_i$ is the mass of the object $\object_i$, and $\Delta t$ is the simulation time step.
Then, the early-termination condition is defined as follows:
\begin{equation}
    \begin{split}
        &E_{\text{kin},i}(t) < \epsilon_\text{kin}\quad \text{for all } i \in \placed_{k+1} \text{ or } \\
        &E_{\text{acc},i}(t) > \epsilon_\text{acc}\quad \text{ for some } i \in \placed_{k+1}    
    \end{split}
    \label{eq:early_termination_condition}
\end{equation}
with the thresholds $\epsilon_\text{kin}, \epsilon_\text{acc} > 0$.

The simulation module is implemented in CUDA using the GPU-accelerated subADMM algorithm \cite{ji2025gpu} which is a scalable and efficient physics simulation algorithm for large-scale rigid body systems with contact.
% We emphasize that, unlike the previous approaches of Johns et al. \cite{johns2020autonomous}, \cite{johns2023framework} which also use the simulation to validate the stability of individual objects, $\simul$ also simulate the overall scene $\scene_{k+1}$ instead of simulating only the newly placed object $\object_{i_{k+1}}$ to ensure that the entire scene is stable.

\subsection{Reward Design}

The reward function is designed to encourage the agent to place objects in a way that maximizes the filled volume of the target shape $\target$ while ensuring the stability of the scene and formulated as follows:
\begin{equation*}
    \begin{split}
        r(\state_k, \action_k) 
        ={}& w_\target\frac{\vol\left(\overline{\scene}_{k+1}\right) - \vol\left(\overline{\scene}_k\right)}{\vol(\target)} + w_\object\frac{\vol\left(O_{i_{k+1}}\cap\target\right)}{\vol\left(O_{i_{k+1}}\right)} \\
        &- w_H\left(\max_{\planar}H_{\scene_{k+1}}(\planar) - \mathbb{E}_{\planar}[H_{\scene_{k+1}}(\planar)]\right) \\
        & - w_D\mathbb{E}_{\mathcal{V}\sim\mathcal{N}(0,\Sigma)}\left[\Delta q_{k+1}(\mathcal{V})\right]- w_S f_\text{eq}
    \end{split}
    \label{eq:reward_function}
\end{equation*}
where $w_\target, w_\object, w_H, w_S, w_D > 0$ are the weight parameters for each reward term and $\overline{\scene}_k := T \cap\bigcup_{i\in\placed_k} O_i(q_i)$ is the intersection of the target shape $\target$ and the union of the placed objects in the scene $\scene_k$.
The first term and the second term encourage the agent to place objects that fill the target shape $\target$ and maximize the filled volume of the target shape $\target$, respectively.
The third term penalizes the height difference between the maximum height and the average height of the scene $\scene_{k+1}$ to encourage a more uniform distribution of objects in the scene.
The fourth term penalizes the expected pose deviation $\Delta q_{k+1}(\mathcal{V})$ of the newly placed object $\object_{i_{k+1}}$ under random perturbations $\mathcal{V}$ sampled from a Gaussian distribution $\mathcal{N}(0,\Sigma)$ to encourage the agent to place objects in a more stable manner.
The last term penalizes the violation of the static equilibrium constraints $f_\text{eq}$ from $\poseopt$ to encourage the agent to place objects in a physically feasible manner.

\subsection{Monte Carlo Tree Search}
Equipped with the modules $\initpose$, $\poseopt$, $\simul$ and the MDP $\mathcal{M}$, we use Monte Carlo Tree Search (MCTS) to explore possible stacking sequences. 


% Given the root state
% $\state_0=(\emptyset,\inventory_0,\target)$, MCTS builds a search tree $\tree$
% whose nodes represent states and whose edges represent placement actions.
% Our batched search is inspired by the parallel Monte Carlo tree search with
% batched rigid-body simulation proposed in \cite{huang2022pmbs}. In contrast to
% that method, we generate geometry-informed placement actions and refine them
% with $\poseopt$ before physical evaluation.

% At the root, we generate a population of candidate actions using $\initpose$
% and $\poseopt$. Promising candidates are locally refined by perturbing their
% planar positions and orientations, while fresh proposals are retained for
% exploration. Each candidate is evaluated by $\simul$, which produces the next
% state and transition reward. During subsequent search, selected actions are
% evaluated in batches through pose optimization and physical simulation. The
% temporary reservations used for batched selection do not modify persistent
% tree statistics:
% \begin{equation*}
%     \ucp(s_t^j,a_t^j) =
%     \frac{Q(s_t^j,a_t^j)}{\visit(s_t^j,a_t^j)+\tmpvisit(s_t^j,a_t^j)}
%     +cP_j
%     \frac{\sqrt{\visit(s_t^j)+\tmpvisit(s_t^j)}}{1+\visit(s_t^j,a_t^j)+\tmpvisit(s_t^j,a_t^j)},
% \end{equation*}
% where $Q_j$ and $\visit_j$ are the accumulated return and completed visit count of child $j$, $\visit_j^\text{temp}$ is the number of virtual visits temporarily reserved for child
% $j$ in the current batch, $P_j$ is its prior probability, and $p$ denotes its
% parent. Virtual visits are used only during batched selection and are discarded
% after the batch is evaluated; they do not modify the persistent tree
% statistics. Progressive widening limits the number of selectable children as
% the number of completed visits increases. The
% geometry- and equilibrium-informed action prior is converted to $P_j$ by a
% softmax over sibling actions. Evaluated rewards are backed up along the
% selected paths.

% Unlike conventional MCTS, we do not perform additional simulation rollouts
% from a leaf node. Every tree transition already requires pose optimization and
% physics-based evaluation, so rollout actions would substantially increase the
% cost of search in the continuous pose space. Instead, we use a truncated
% finite-horizon search. Let $H$ be the maximum search depth and let
% $\state_d$ be a nonterminal leaf at depth $d$. Its remaining value is
% estimated by
% \begin{equation*}
%     \hat{V}(\state_d)
%     =
%     \bar{r}\sum_{j=0}^{h_d-1}\gamma^j,
%     \qquad
%     h_d=\min\{H-d,\lvert\inventory(\state_d)\rvert\},
% \end{equation*}
% where $\bar{r}$ is a heuristic mean transition reward estimated from evaluated
% placements. Thus, the estimator accounts for the remaining construction
% horizon without introducing additional rollout simulations. Terminal and
% failed leaves do not receive this bootstrap value.

% After the search budget is exhausted, root actions are ranked using both their
% mean backed-up return and the return of a physically validated continuation:
% \begin{equation*}
%     a^*=\argmax_{a\in\mathcal{A}_{\mathrm{val}}(\state)}
%     \left[(1-\lambda)\overline{Q}(\state,a)
%     +\lambda G_{\mathrm{val}}(\state,a)\right],
% \end{equation*}
% where $\mathcal{A}_{\mathrm{val}}(\state)$ contains physically validated root
% actions with an available validated continuation, $\overline{Q}$ is the mean
% backed-up return, and $G_{\mathrm{val}}$ is the discounted return along that
% continuation, including the immediate placement. Only the selected immediate
% placement is executed; its subtree may be reused as the root for the next
% planning step.
